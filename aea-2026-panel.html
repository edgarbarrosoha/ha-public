What is evaluated

Two criteria, five questions about the design.

Both criteria come from the OECD-DAC evaluation criteria (2019), adapted to EID 2026.

Criterion 1RelevanceDoes the design respond to documented needs?
Criterion 2CoherenceAre the instruments compatible with each other?
1.1Alignment with needs

Do instruments address the problems and the people that the evidence documents?

What is comparedPublic problem and target population, compared with an independent reference diagnosis
1.2Capacity to affect the problem

Can the design solve the problem it declares?

What is comparedSix design elements, from causes and effects to means, ends and assumptions
2.1Between levels of intervention

Do lower levels of intervention serve the objectives of higher ones?

What is comparedNational plan, 14 sectoral and institutional programs, 99 budget programs
2.2Between orders of government

Do state plans align with the national plan?

What is comparedThe national plan and the 32 state development plans, as declared and in substance
2.3Horizontal coherence

Do programs at the same level complement, duplicate or contradict each other?

What is comparedPairs of programs that share an axis category

Each subcriterion has its own rubric, agreed with INEGI before the models read the documents.

The record

Changing one character in a record breaks the chain of fingerprints.

What we didThe system writes each run to an append-only record. Each record carries the hash of the one before; the last hash is anchored outside the file.

What forA third party can check, offline and without the system, that the record was not altered after the run.

How to read this screenBoxes: the first records of the methodology files and settings a run applied. Press "Verify", change one character in record 2, and verify again: the verdict names where the chain breaks.

WHORecord and verifier: Óscar Díaz and the engineering team.

Hash (SHA-256)A 64-character fingerprint computed from a text. Changing one character changes it.
Hash chainEach record carries the hash of the one before, so a change to one record breaks the link to the next.
AnchorThe hash of the last record, kept outside the file in cadena.txt. Any change to the chain, even a full rewrite, no longer matches it.
Append-only recordA file where entries are only added at the end; earlier entries are never edited.

Model families can agree on a corrupted text, so legibility is checked before any model reads.

What we didBefore the run, a review checked whether the text of the PDFs could be read. Corrupted text was repaired, and the repair was recorded as a step of the process.

Why the jury did not catch it

Model families of different lineage reading the same corrupted text would agree with each other, with high confidence. Agreement measures the reasoning; the source needs a separate check.

Text layerThe characters a PDF stores, which text extraction hands to the model.
Corrupted text layerCharacters written with one character table and read with another; accented letters arrive as other symbols.
Image onlyA scanned PDF with no text layer. Its pages go through OCR (optical character recognition).
DiagnosticThe document in which a program states the problem it addresses, with its causes and effects.
What changed

The repair became a declared step of the process (INEGI's PDF stays untouched; the repaired text carries a separate fingerprint), scanned pages went through managed OCR, and a precondition metric was added: below a coverage threshold a unit is reported "indeterminate by source coverage", never "non-existent".

The published rationale (literal, Spanish) and the reviewer's reason

Ratings where the families voted the same, by construct

In capacity, 154 of the 173 "ambiguous" ratings with two "clear" votes against came from the same family. Under a "most severe vote" rule, the strictest judge decides each disagreement.

ClearThe element is present, consistent with the external reference and meets all its necessary conditions.
AmbiguousThe element is present but incomplete, partly corresponding or not verifiable in some component.
Non-existentThe element is absent, or its content contradicts the reference or the instrument's diagnosis.
Most severe voteThe rule in force, written in code before the run: under disagreement, publish the lowest vote on this scale and send the case to a person.
How votes combine is code

Three rules, the same votes: the result changes for 253 of 551 units.

What we didWe kept each vote as a closed record and wrote the rule that combines the votes as code. Then we combined the same votes under three rules.

What forThe effect of a rule on the result can be examined without calling a model again. Its consequences can be reviewed before a result is published.

ComplementaritySame population with different kinds of support, or similar support for different populations: the effects add up toward a shared goal.
Partial duplicationSimilar objectives and support for the same population, with no declared division of scope; the overlap covers only part of the programs.
Votes differThe model families disagree. The pair gets no category and a person decides.
IndependenceThe pair was examined and shows no relevant relation: no shared population, problem or support that would sustain another category. It is counted, not drawn.

Each pair joins two programs of the same level: 1,021 pairs of budget programs and 91 pairs of sectoral and institutional programs. "Other sectors" holds 7 budget programs from 4 sectors with one or two programs each: infrastructure and communications, science, indigenous peoples and women. A review from the documents found the input incomplete in most pairs, so this construct is the most likely to change. No pair was classified as a contradiction: meeting what one program sets out impedes meeting what the other sets out. Programs are not named in this session.
